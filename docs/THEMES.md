# Оформление — 0.5.0

## Поведение

В настройках оформления перед переключателем прозрачности находится «Тема»: тёмная (по умолчанию) и светлая. Режима следования Windows нет. Меняются цвета, прозрачность, тени и блики; геометрия и редактор сохраняются. Тёмные значения оставлены fallback-значениями CSS. Светлая палитра задана семантическими переменными в `src/themes.css`, применяется через `html[data-theme="light"]` и `color-scheme`.

Основные поверхности: фон `#EEEFF3`, полотно `#FCFCFD`, панели `#F5F5F8`. Текст `#111113`, подписи `#50515B`, подсказки `#686975`, акцент `#69528F`. Контраст шести текстовых ролей на трёх основных поверхностях проверяется браузерным тестом: минимум 4,73:1. Disabled-контролы сохраняют принятую прозрачность. Цветовые группы клавиатуры и четыре маркера имеют отдельные светлые варианты. Фотографии не фильтруются; JSON маркеров и HTML-экспорт не зависят от темы.

## Сохранение и запуск

`AppearancePreferences { theme: "dark" | "light" }`, типизированные команды `appearance`, `setAppearance` и `appearanceReady`. Rust сохраняет `appearance.json` атомарной заменой файла после `sync_all`. Файл находится рядом с каталогом `vault`, содержит только тему, не входит в зашифрованную копию дневника и доступен до разблокировки. Ошибка чтения или повреждение файла дают безопасное значение `dark`; произвольные поля и неизвестные темы при записи отклоняются.

Frontend последовательно выполняет изменения оформления, отображает выбор сразу и при ошибке возвращает последнюю успешно сохранённую тему. Переключатель недоступен до завершения текущего сохранения. Редактор не перемонтируется. Окно стартует скрытым: Rust применяет тему рамки и фон, frontend загружает палитру и рисует интерфейс, затем `appearanceReady` показывает окно. Блокировка очищает документы как раньше, но не тему. Схема SQLCipher остаётся 4; настройки оформления не меняют ревизии записей и задач.

Для Windows используются `set_theme`, цвет фона окна/WebView и `ICoreWebView2Profile::SetPreferredColorScheme` для встроенных меню WebView2. Старый runtime без интерфейса профиля сохраняет собственное оформление системного меню; UI и рамка продолжают работать. Нативные диалоги выбора файлов остаются диалогами Windows: используемый dialog plugin не предоставляет отдельного параметра их палитры, их вид зависит от ОС. Собственных замен системных диалогов нет.

## Проверки 24 октября 2026

- Rust: 32 теста. Добавлены отсутствие/повреждение файла, чтение после записи, отклонение неизвестных значений и ошибка атомарной записи. Существующие тесты шифрования, восстановления и экспорта проходят.
- Vitest: 5 тестов. В том числе сериализация быстрых запросов, возврат последней подтверждённой темы при ошибке и тёмный fallback при ошибке чтения.
- Playwright/Edge: переключение в настройках, сохранность DOM редактора, текста, undo и размеров; светлый Планер, карточка, задача, вложенные исполнители, клавиатура, узкое окно 650 px, непрозрачный режим, возврат после ошибки записи и контраст. Полная регрессия включает дневник, маркеры, ссылки, связанные задачи, изображения, исполнителей и drag-and-drop.
- Нативный `scripts/native-themes.mjs` создаёт отдельный профиль: светлый первый экран, смена темы через настройки, проверка файла, неизменность записей/Планера, принудительный перезапуск, вход и блокировка, тёмный fallback после повреждения только тестового файла оформления. Снимки экрана и JSON-отчёт находятся в `artifacts/themes-native-*/`.
- `native-planner.mjs` и `native-smoke.mjs` поддерживают `NOT_STUDIO_TEST_THEME=light` для прогона реального сохранения, импорта изображения, переноса карточек, восстановления черновика и ключа в светлой теме. Личный профиль не используется.

Browser plugin not available: визуальная автоматизация выполнена существующим Playwright проекта. Просмотрены снимки светлого дневника, Планера, карточки, окна задачи, настроек, клавиатуры, вложенных исполнителей и экрана входа; снимки браузерных проверок сохраняются во временной папке Windows.

Нативные прогоны выполняются с собранным Windows executable и тестовым профилем при фактическом DPI 125%. Это не подтверждает ручную установку поверх предыдущей версии, физическое взаимодействие с системными меню, отсутствие вспышки на всех конфигурациях GPU или полную матрицу Windows 100/150/200%. Эти проверки остаются ручными. Актуальный итог прогона и SHA-256 установщика — в `ACCEPTANCE.md` и `releases/SHA256SUMS.txt`.
