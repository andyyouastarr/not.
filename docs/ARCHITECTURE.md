# Архитектура

В 0.1.6 клики по ссылкам и Enter на сфокусированной ссылке передаются типизированной команде `openLink`. Rust проверяет, что дневник разблокирован, валидирует URL и разрешает только HTTP/HTTPS/mailto. В Windows `ShellExecuteW` вызывается на UI-потоке без командной оболочки, вне мьютекса хранилища. Ошибка системного открытия возвращается в интерфейс. WebView остаётся на странице дневника; выделение текста ссылки не вызывает переход. В браузерном демо используется отдельное окно с `noopener,noreferrer`.

В 0.1.4 хронология и клавиатура объединены в левую колонку `entry-column`; область прокрутки записи остаётся отдельной. Ширина колонки обновляется во время перетаскивания через CSS-переменную, подтверждённое значение сохраняется в настройках. Новое минимальное значение ширины — 300 px; UI ограничивает её 520 px и шириной окна. Исторические значения до 1200 px по-прежнему принимаются при чтении/сохранении настроек. Toolbar использует `position: sticky` внутри области прокрутки; непрозрачный фон и отдельный z-index сохраняют читаемость и доступность меню поверх текста.

В 0.1.3 ширина клавиатуры хранится в необязательном поле настроек `keyboardWidth` (440–1200 CSS px); при узком окне фактическая ширина ограничена свободным местом. Маркер — inline mark Tiptap `highlight` с именем цвета `lavender`, `yellow`, `green` или `pink`. Rust отклоняет неизвестные цвета. Экспорт строит `<mark>` только из фиксированного набора безопасных значений и использует палитру для светлого фона. Изменения схемы SQLite не требуются, однако редакторы до 0.1.3 не понимают новый mark; обратное редактирование такими версиями не поддерживается.

Клавиатура-подсказка: отдельная команда `keyboard_state` считывает состояние на UI-потоке, вне мьютекса хранилища. Проверяется принадлежность активного окна приложению, затем через `GetGUIThreadInfo` определяется поток сфокусированного дочернего окна WebView2 и его `GetKeyboardLayout`. Варианты различаются по полному идентификатору, а не только языку. `GetKeyState` читает Caps Lock; события клавиатуры редактора уточняют индикатор. Глобальных перехватчиков и записи нажатий нет. Панель запрашивает состояние каждые 75 мс после завершения предыдущего запроса, только когда видима и приложение в фокусе; при возвращении выполняется немедленный запрос. Видимость и высота — необязательные поля зашифрованных настроек, без изменения схемы базы.

Системные API: [GetGUIThreadInfo](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getguithreadinfo), [GetKeyboardLayout](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getkeyboardlayout), [GetKeyState](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getkeystate).

React/TypeScript управляет состоянием экрана и документом Tiptap. Rust — единственный слой постоянного хранения. API `dispatch` принимает размеченное перечисление команд; SQL и произвольные пути из UI не принимаются. Выбор файлов происходит в системных диалогах Rust. Схемы команд зеркально описаны в `src/types.ts` и Rust `Request`; ошибки возвращаются без содержимого записей и ключей.

В базе находятся записи с UUID, календарной датой, временем создания/изменения и ревизией. Сохранение проверяет ожидаемую ревизию и меняет документ вместе с FTS5-индексом в одной транзакции. JSON проверяется по допустимым типам блоков, глубине, размеру, ссылкам и идентификаторам вложений. Чек-листы пока не являются сущностями планировщика. `PRAGMA user_version=1`; неизвестная версия отклоняется. Будущая миграция должна начинаться с проверенной резервной копии; первая схема создаётся атомарно, предыдущих схем пока нет.

## Ключи

При создании генерируется 256-битный случайный master key. Из него стандартной libsodium KDF выводятся отдельные ключи для SQLCipher и файлов. Пароль преобразуется в ключ с Argon2id (`OPSLIMIT_INTERACTIVE`, `MEMLIMIT_INTERACTIVE` libsodium); версия параметров закреплена версией manifest. Master key запечатан `secretbox` отдельно ключом пароля и случайным 256-битным recovery key. У каждой обёртки своя случайная nonce.

Recovery key показывается пользователю для сохранения и проверяется повторным вводом. До подтверждения временная копия находится **внутри зашифрованной базы**, чтобы прерывание первого запуска не оставляло пользователя без ключа. После подтверждения она удаляется при включённом secure_delete. Master key, производные ключи и SQLCipher-соединение остаются в Rust. UI получает recovery key только в ходе первоначальной настройки; master key никогда не передаётся.

Секретные Rust-типы libsodium обнуляют память при освобождении, промежуточные буферы дополнительно zeroize. WebView размонтирует редактор, очищает состояние и отзывает object URL при блокировке. Это не является гарантией стирания всех копий из управляемой памяти WebView, файла подкачки, дампов ОС или чужих программ. Защита предназначена для данных на диске при закрытом хранилище, а не для заражённого или разблокированного компьютера.

## Файлы и копии

С 0.1.1 длина расшифрованного вложения сверяется с сохранённым исходным размером перед предпросмотром и экспортом. При добавлении файл проверяется обратным чтением до регистрации в БД. Это выявляет неполные вложения 0.1.0, где очистка `Vec` обрывала чтение после первых 64 КиБ. При очистке повторно используемого рабочего буфера теперь обнуляется срез, без изменения длины.

У изображений есть необязательные атрибуты JSON `widthPercent` (15–100) и `layout` (`block`/`left`/`right`). Это внутреннее представление: пользователь меняет размер и перетаскивает изображение, а размещение вычисляется автоматически. Атрибуты проверяются в Rust и учитываются в HTML-экспорте. Высота определяется исходными пропорциями. CSS float привязывает изображение к следующему текстовому блоку; ширина в процентах позволяет адаптироваться к окну. Произвольных абсолютных координат нет. Таблицы, разделители и блоки кода очищают обтекание.

Вложения используют аутентифицированный libsodium XChaCha20-Poly1305 secretstream, блоки по 64 КиБ с обязательным финальным тегом. Ошибки аутентификации, обрезание и лишние данные отклоняются. Исходные имена скрыты в зашифрованной базе; на диске используются UUID. Файл сначала записывается и синхронизируется, затем регистрируется в БД. Осиротевший зашифрованный файл после аварии безопасен; автоматического удаления вложений пока нет, поскольку корзина обратима.

SQLCipher требует наличия `cipher_version`, иначе приложение отказывается работать. Временные SQL-данные находятся в памяти, `synchronous=FULL`, `secure_delete=ON`. Поисковый индекс шифруется вместе с базой. Приложение не пишет личное содержимое в localStorage, журналы или открытые временные файлы. Явный экспорт и сохранение вложения создают открытые файлы по выбору пользователя.

Архив — контейнер с зашифрованным снимком SQLCipher, manifest и зашифрованными вложениями. Снимок создаётся через SQLite Backup API в другое зашифрованное соединение при сериализации операций хранилища. Копия завершается атомарным переименованием. Формат архивов ограничен 4 ГБ при восстановлении, база — 512 МБ, файл — 25 МБ; это предохранители личной v1, не ограничения SQLite.

Восстановление запрещает traversal, символьные ссылки, дубликаты и неизвестные пути. В отдельной папке проверяются пароль, integrity_check, документы и аутентификация всех вложений. Только после проверки предыдущее хранилище откладывается и заменяется. Автоматические копии создаются при открытии и раз в минуту проверяют наступление нового дня; первая копия дня не перезаписывается.

## Системный слой и развитие

Дисковые и криптографические операции выполняются в блокирующем worker pool, не на UI-потоке; доступ к единственному хранилищу сериализуется mutex. Длинная операция может задержать фактическое освобождение ключей при блокировке до своего завершения. Перед публичным релизом стоит добавить отмену длительных файловых операций и независимый аудит безопасности.

Публичных серверных API нет. Для будущего планировщика создаётся отдельная сущность задачи со ссылками из записей; экран дня показывает эти задачи без копирования. Синхронизация требует отдельного протокола версий, удаления, конфликтов и распределения ключей. Синхронизировать открытый файл SQLite через облачную папку нельзя.
