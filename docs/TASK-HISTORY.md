# История задачи — 0.6.0

В окне задачи доступны вкладки редактирования (или просмотра) и истории. История показывает создание и переходы: старые дни сверху, внутри дня — стадии по первому посещению, внутри стадии — все посещения с временем. Названия стадий сохраняются на момент события. Подсказка времени содержит секунды и UTC-смещение места совершения действия.

Редактор остаётся смонтированным при переключении. Сохранить и Отменить относятся к задаче, а не к открытой вкладке; зашифрованный черновик продолжает сохраняться. История перечитывается при открытии, загружается страницами по 200 событий. Ошибку можно повторить внутри вкладки. Ответ закрытой вкладки игнорируется.

## Хранение и отчёты

Схема 5 расширяет `planner_task_events`. Модуль `src-tauri/src/history.rs` записывает события в транзакции изменения задачи. Переход и завершение одной операции имеют одинаковые operation ID и время. Сохраняются UTC, местная дата и смещение, ревизия, снимки названий задачи, стадий, исполнителя и прежнего исполнителя, признаки завершения, архива и корзины. Для правок сохраняется только перечень полей `title`, `document`, `deadline`; содержимое описания в события не копируется.

Типы: `created`, `moved`, `assigned`, `reassigned`, `unassigned`, `completed`, `reopened`, `edited`, `archived`, `unarchived`, `deleted`, `restored`, `baseline`. Перестановка внутри стадии, пустое сохранение, черновик и неуспешная операция события не создают. Изменение признака завершения стадии записывает завершение/возобновление без перехода. Удаление стадии создаёт переходы с причиной `stageSettings`, в том числе у архивных и удалённых задач. Отмена связанного создания — `deleted` с причиной `undoCreation`.

Команда `taskHistory` принимает `query`:

```json
{
  "taskId": null,
  "from": "2026-10-01",
  "to": "2026-10-31",
  "assignee": { "mode": "all" },
  "kinds": ["created", "moved"],
  "cursor": null
}
```

`from`/`to` включительны и относятся к сохранённой местной дате. Отсутствие даты не подменяется датой UTC. Исполнитель: `all`, `none` или `person` с `id`. Для событий назначения проверяются обе стороны назначения. Это ответственный на момент действия, а не автор. Пустой `kinds` означает все типы. Ответ — `events` и `next`; курсор передаётся без изменений вместе с прежними фильтрами. Он фиксирует верхнюю границу ID, чтобы появившиеся позже события не нарушали текущую пагинацию. Индексы предусмотрены для задачи/времени, даты и исполнителей.

Журнал — основа будущих выборок, не измерение рабочего времени. `baseline` нужно исключать из подсчётов активности. Интерфейса общих отчётов в выпуске нет.

## Миграция и восстановление

Перед переходом 4 → 5 создаётся отдельная зашифрованная копия в `migration-backups`; все её ZIP-компоненты проверяются чтением с CRC до изменения схемы. Миграция транзакционная. События схемы 4 сохраняют исходные UTC и payload, новые неизвестные сведения остаются NULL; API помечает их `incomplete`. Для существующих задач создаётся отдельное исходное состояние на момент обновления, а вкладка поясняет дату начала полной истории. Прежние переходы не восстанавливаются задним числом.

Пароль и recovery key прежние. Старые резервные копии проходят последовательные миграции. Восстановление проверяет задачи, события, ревизии, даты, снимки и ссылки; удалённые стадии разрешены через исторические снимки. Для возврата к 0.5.0 нужна копия до миграции.

## Проверки

Автоматизация: Rust-тесты в `history.rs`, существующие тесты назначений/связей, `src/planner/history.test.ts`, `tests/history.spec.ts`, `scripts/native-history.mjs`. Нативные сценарии используют отдельные синтетические профили в игнорируемом `artifacts/`; личное хранилище не открывается.

Нативный прогон использует debug-приложение с встроенным production frontend и WebView2/CDP, не заменяет ручную установку NSIS. Фактический масштаб среды 125%; Windows 100/150/200% отдельно не проверялись. Детальная ручная проверка переключения истории непосредственно во время импорта изображения, сохранения прокрутки/выделения на длинном реальном документе, физического системного меню и обновления установленной программы остаётся в ручной приёмке. Общие сценарии импорта, undo/redo, блокировки, исполнителей, ссылок и переноса проверены автоматизацией.
