# Приёмка not. studio

## Вставка изображений и таймер — 0.1.7

26 сентября 2026: пройдены 3 unit-теста TypeScript, 19 Rust-тестов, 14 браузерных сценариев и Clippy `-D warnings`. После уточнения текста настройки, частоты отправки активности и защиты от завершения старой вставки повторены два новых браузерных сценария. Production-сборка проходит.

- Изображение из paste вставляется в запись; переход в другую запись ожидает завершения импорта. Проверены повторное открытие записи, undo/redo, декодирование целой картинки и ошибка повреждённого содержимого без изменения текста.
- Rust проверяет декодирование PNG и лимиты до записи, шифрование вложения, чтение без потери байтов, отклонение повреждённых/слишком больших данных, резервную копию и восстановление изображения вместе с настройкой отключённого таймера.
- Настройки: значение по умолчанию 30, все готовые интервалы, «Никогда», произвольное значение 7 минут, сохранение при повторном открытии диалога, отклонение 241 минуты. Проверена граница таймера: до срока не блокируется, на сроке блокируется; 0 отключает таймер, но не условие блокировки Windows.
- Нативный Tauri/WebView2 с отдельным хранилищем: настоящий Windows clipboard bitmap и CF_HDROP со скопированным PNG вставлены через Ctrl+V. Обе картинки восстановились после принудительного завершения и открытия ключом восстановления. «Никогда» сохранился после перезапуска и оставил дневник открытым в течение контрольных 65 секунд. Переключение на одну минуту привело к фактической блокировке. Отчёт — `artifacts/native-smoke.json`; сценарий запускается с `NOT_STUDIO_TEST_PASTE_IDLE=1` после `-Mode build-smoke`. Вспомогательный процесс держит прежний буфер обмена в памяти и восстанавливает его после проверки.

Дополнительно выполнен `NOT_STUDIO_TEST_PASTE_RACE=1`: декодирование картинки искусственно задержано, подан запрос блокировки, хранилище закрыто и открыто заново. Завершение старой операции не вставило картинку в открытый дневник и не заблокировало новую сессию. Отчёты сохранены отдельно: `artifacts/native-paste-idle.json` и `artifacts/native-paste-race.json`.

Проверки выполнялись на Windows 10 / WebView2 при масштабе 150%. Реальный Win+L в пользовательской сессии не вызывался: независимость системной блокировки проверена на уровне функции принятия решения; полный ручной прогон с блокировкой Windows остаётся в матрице приёмки. Копирование из конкретных версий браузеров и «Ножниц» требует отдельного ручного прогона; нативно проверены форматы bitmap и файлового списка Windows. Схема базы не меняется. После сохранения новой настройки используйте версию 0.1.7 или новее.

## Переход по гиперссылкам — 0.1.6

18 сентября 2026: 3 unit-теста TypeScript, 17 Rust-тестов, все 12 браузерных сценариев, Clippy `-D warnings` и production-сборка интерфейса пройдены. Исправление дополняет отключённый стандартный переход Tiptap собственным обработчиком: WebView не покидает дневник, адрес передаётся в Rust и открывается средствами Windows.

- Браузер: назначение и сохранение URL, открытие после перехода между записями, обычный клик и Enter, сохранение адреса с query/fragment, редактирование выделенного текста ссылки без перехода. Файловый URL при назначении отклоняется.
- Rust: независимая проверка разрешённых схем HTTP/HTTPS/mailto, отклонение file/javascript/data/системных схем, путей к файлам, управляющих символов и слишком длинных адресов. URL передаётся системной функции напрямую, без командной оболочки.
- Нативный прогон с `$env:NOT_STUDIO_TEST_LINK='1'`: ссылка назначена через интерфейс в отдельном тестовом дневнике. После сохранения, принудительного завершения и открытия ключом восстановления клик вызвал системный обработчик Windows; временный HTTP-сервер на 127.0.0.1 получил запрос по уникальному тестовому адресу. URL WebView остался `http://tauri.localhost/`, текст записи и чек-листы сохранились. Прямой вызов команды с file URL отклонён. Отчёт — `artifacts/native-smoke.json`. Тест открывает одну диагностическую вкладку браузера, которую можно закрыть.

Установщик NSIS 0.1.6 собран 18 сентября; 19 сентября проверено совпадение SHA-256 исходного установщика, копии в `releases` и файла контрольных сумм. Проверено на Windows 10 / WebView2 при масштабе 150%. Само открытие почтовой программы для mailto не проверялось. Данные и схема хранилища не меняются.

## Чек-листы — 0.1.5

Нативный Tauri/WebView2 со встроенным интерфейсом и отдельным профилем: после подтверждённого сохранения и принудительного завершения приложения первый пункт остался отмеченным, второй — неотмеченным. Повторное открытие выполнено ключом восстановления. Схема данных и криптография не изменены; новые Rust-тесты для изменения интерфейса не добавлялись. Проверено на Windows 10 при масштабе 150%; полная матрица Windows 11 остаётся отдельным этапом.

- 4 сквозных прогона Tauri/WebView2 выполнены для PNG (1 242 414 байт), JPEG (257 716), WebP (273 288), GIF (565 645). Расшифрованные файлы совпали с оригиналами по SHA-256; нижняя часть каждого изображения декодирована.
- Проверены изменение размера мышью с пропорциями, ввод текста в освободившемся месте, перетаскивание вправо, геометрия обтекания, undo/redo и сохранение размера/положения после принудительного закрытия. Переключателей режимов в UI нет.

- Старые документы совместимы: отсутствующие атрибуты ширины/размещения получают значения по умолчанию. Изменений схемы SQLCipher нет.

## Ручная приёмка перед ежедневным использованием

1. На Windows 11 установить приложение, создать тестовый дневник, сохранить recovery key отдельно и подтвердить его вводом.
2. Написать несколько длинных записей. Проверить переносы, списки, undo/redo, перестановку блоков, фото, файл и таблицу. Перезапустить и сравнить содержимое.
3. Сделать резервную копию на другой носитель, восстановить в чистом профиле и проверить текст и файлы. Отдельно проверить неправильный пароль и повреждённую копию.
4. Проверить реальную блокировку Windows, сон и пробуждение, 5 минут бездействия, закрытие с несохранёнными изменениями и нехватку места на тестовом диске.
5. На Windows 11 при 100%, 150% и 200% масштаба рабочего стола проверить читаемость и все действия при минимальном размере окна. Проверить высокий контраст и системный экранный диктор.
6. Две недели вести дневник ежедневно: записывать найденные неудобства, задержки и ошибки. Не считать этот этап выполненным по результатам синтетических тестов.

Установщик первой личной сборки не имеет приобретённого сертификата подписи кода. Для публичного выпуска потребуется отдельный процесс подписания и проверки установок/обновлений.
