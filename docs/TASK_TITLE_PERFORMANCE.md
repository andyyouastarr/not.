# Отклик названия задачи — 14 ноября 2026

## Повторная диагностика и исправление 0.6.3

Пользователь подтвердил: 0.6.2 не устранила задержку; тормозит только название.
В нативном тесте с 90 синтетическими задачами воспроизведена задержка до доставки
`keydown` странице. Два символа: название 1962 мс, описание 29 мс.
Отключение spellcheck/autocomplete, прозрачности и замена showModal на show
не устраняли задержку. CPU-профиль не показал тяжёлой работы React во время паузы.

Причинный A/B/A опыт: удаление только select стадий из закрытых меню карточек
сократило ввод до 7 мс; возвращение тех же элементов вернуло задержку 1425 мс.
Артефакты: `artifacts/input-diagnostic-native-1794614279866`.
Это локализует проблему в обработке WebView2 большого количества select в DOM;
конкретная внутренняя подсистема браузера без native trace не установлена.

Исправление: CardMenu монтирует содержимое details только при открытии и снимает
его при закрытии. Разметка, доступность summary, меню стадий и drag-and-drop сохранены.
После исправления на той же синтетической доске название: 7 мс, описание: 25 мс;
контрольные варианты: 5–9 мс. Артефакты:
`artifacts/input-diagnostic-native-1794614420538`.
9 браузерных сценариев Планера/переноса/ввода прошли; дополнительно прошла проверка
300 карточек с отсутствием скрытых select и появлением/удалением select при toggle.
TypeScript/Vite и нативная debug-сборка успешны.

Пользователь разрешил проверить открытую программу и изменить название задачи.
Computer Use прочитал дерево, но захват кадра завершился `FrameArrived timed out`,
а клик — `coordinate input geometry is unavailable`. Названия не изменялись.
Измерения выше относятся исключительно к отдельному тестовому хранилищу.

Скрипт воспроизведения: `DIAGNOSTIC_TASKS=90 node scripts/native-input-diagnostic.mjs`
(переменную в PowerShell задавать через `$env:DIAGNOSTIC_TASKS='90'`).

## Симптом и границы диагностики

Пользователь сообщает задержку 1–2 секунды при вводе названия как новой пустой,
так и существующей задачи; задач меньше 100. Личное хранилище не открывалось.
Саму задержку на пользовательских данных не считаем воспроизведённой.

## Подтверждённые лишние операции

- Каждое изменение `draft.title` перерисовывало `JournalEditor`. Его новые объекты
  расширений и editorProps заставляли Tiptap вызывать `setOptions`, обновляя view.
  Один и тот же тест посимвольного ввода до исправления зарегистрировал 45 вызовов,
  после — 0. Экземпляр редактора и документ остаются прежними.
- Начальное описание сериализовалось через `JSON.stringify(initial)` при каждом
  рендере: выражение аргумента `useRef` всё равно вычисляется. Теперь это однократная
  ленивая инициализация.
- Автосохранение через `plannerChange/draft` читало всю доску, клонировало её и
  возвращало все описания задач через IPC, хотя окно не использовало этот ответ.
  Новый `savePlannerDraft` проверяет и записывает только черновик, возвращает boolean.

Редактор описания мемоизирован только внутри окна задачи; его обработчики стабильны.
Изменение описания, режима редактирования и доступности Timestamp продолжает
обновлять необходимые props. Задержка автосохранения 500 мс, очередь, flush,
валидация вложений и шифрование сохранены. Схема БД не меняется.

## Проверки

- 37 Rust-тестов: в том числе автосохранение при недоступной таблице задач,
  неизменность задач и ревизии доски, отказ записи, неверный заголовок,
  восстановление черновика после открытия и из резервной копии.
- 8 unit-тестов; 41 браузерный сценарий. После уточнения стабильных callbacks
  отдельно повторён тест ввода с проверкой undo/redo описания.
- TypeScript/Vite production build и Clippy all-targets с запретом предупреждений.
- Browser plugin not available: использован существующий Playwright/Edge.
  Снимок: `artifacts/task-title-performance.png`; ошибок страницы не обнаружено.
- Нативный воспроизводимый замер: `scripts/native-title-performance.mjs`.
  Создаёт отдельное тестовое хранилище с 90 синтетическими задачами и сравнивает
  ответы старой и новой команды, проверяет ввод и фактическое сохранение черновика.

Нативный результат: `artifacts/title-performance-native-1794605102458/result.json`.
Синтетическая доска содержит 90 задач по 20 текстовых абзацев (без изображений).
В пяти замерах старая команда занимала 320–374 мс, новая — 3,4–5,9 мс.
Сериализованный ответ сократился примерно с 2,7 МБ до `true` (4 символа).
Это длительность запроса через тестовый CDP-клиент в debug-сборке, а не время
от физического нажатия клавиши до появления символа. Снимок `title.png`
сохранён в том же каталоге. Первая серия дала 328–354 мс против 3–9 мс.

Ограничение замера ввода: первый нативный `pressSequentially` превысил 30 секунд.
Контрольный тест трёх символов в обычном DOM-input без React также медленный:
1,31 секунды с прозрачностью и 2,66 секунды без неё (название задачи: 2,08 и
3,26 секунды соответственно). После события `input` ближайший animation frame
приходил за 1,8–4,9 мс, но это не измеряет фактическую презентацию кадра.
Поэтому ни полное устранение пользовательской задержки, ни виновность glass/GPU
по этим данным не утверждаются. Нативный `passed` подтверждает содержимое
черновика и отсутствие ошибок страницы, а не порог быстродействия клавиатуры.

Исправления включены в установщик `releases/not-studio-0.6.2-windows-x64-setup.exe`
(13 464 359 байт). Release-сборка и упаковка NSIS завершились успешно.
