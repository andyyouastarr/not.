# not. studio

Локальный дневник для Windows: тёмная студия, блочный редактор и зашифрованное хранилище. Первая версия ориентирована на личное использование. Планировщик и экран дня остаются следующими отдельными выпусками.

## Готовая сборка 0.1.1

[Установщик Windows x64](https://github.com/andyyouastarr/not./releases/download/v0.1.1/not-studio-0.1.1-windows-x64-setup.exe). Для обновления создайте резервную копию, сохраните запись и закройте приложение перед запуском установщика. На экране «Уже установлено» выберите «Не удалять». Хранилище остаётся по прежнему пути; смена пароля и миграция базы не нужны. При первом запуске создайте пароль и сохраните ключ восстановления. Node.js, Rust и сервер разработки для использования не нужны. При отсутствии WebView2 установщик предложит его загрузку.

В 0.1.1 исправлено обрезание вложений больше 64 КиБ. Старые неполные файлы автоматически восстановить нельзя: добавьте их заново из оригиналов. Для неполной картинки редактор показывает сообщение и кнопку **«Заменить исходным изображением»**. Это касается и файловых вложений, добавленных в 0.1.0; копия старого хранилища не восполняет отсутствующие байты.

Картинки меняют размер за нижний угол, сохраняя пропорции. Уменьшенную картинку можно перетащить к левой или правой стороне нужного абзаца — текст обтекает её автоматически. Крупная картинка занимает отдельную строку. Отдельных переключателей размещения нет. Ширина хранится как доля полотна; размещение привязано к тексту, сохраняется в записи и HTML-экспорте. Перестановка и изменение размера поддерживают undo/redo. На маркере размера работают стрелки ←/→ и Home/End.

Сборка не подписана сертификатом издателя. Проверена на Windows 10; целевая приёмка Windows 11 и две недели ежедневного использования ещё впереди. [Проверки и ограничения](docs/ACCEPTANCE.md).

## Возможности

- Записи по датам, хронология, календарный фильтр, полнотекстовый поиск, избранное и восстановление из корзины.
- Tiptap: текст, заголовки, списки и чек-листы, цитаты, ссылки, таблицы, изображения и вложения до 25 МБ. Добавление через `+` или `/` в начале пустого блока; перемещение текущего блока стрелками и перетаскиванием ручки.
- Автосохранение через 500 мс; последовательная очередь учитывает правки во время сохранения. Ошибка не снимает признак несохранённых изменений.
- Режим фокуса, сворачиваемые панели, виртуализация карточек, уменьшение прозрачности, системная настройка уменьшения анимации.
- SQLCipher, Argon2id, libsodium secretstream, пароль и независимый recovery key.
- Ежедневные зашифрованные резервные копии (последние 7), ручные копии, проверка восстановления в отдельной папке и открытый HTML-экспорт с вложениями.

## Разработка и сборка

Нужны Windows, Node.js 22+, Rust MSVC, Visual Studio C++ Build Tools с Windows SDK, WebView2 и **нативный Strawberry Perl** для сборки OpenSSL. Perl из Git/MSYS не подходит. Версии зависимостей закреплены в `package-lock.json` и `src-tauri/Cargo.lock`.

```powershell
npm ci
pwsh -File scripts/build-windows.ps1 -Mode dev
pwsh -File scripts/build-windows.ps1 -Mode test
pwsh -File scripts/build-windows.ps1 -Mode bundle
```

При отсутствии PowerShell 7 используйте `powershell -ExecutionPolicy Bypass -File ...` вместо `pwsh -File ...`. Параметр действует только на этот процесс.

Установщик создаётся в `src-tauri/target/release/bundle/nsis/`. Перед чистой сборкой выполните `cargo fetch --locked --manifest-path src-tauri/Cargo.toml`; скрипт сборки использует локальный кэш. При тайм-аутах транспорта Cargo предусмотрен `python scripts/cargo-cache.py`: он загружает пакеты с официального crates.io по HTTPS и проверяет SHA-256 из индекса. Он не меняет TLS, учётные данные или настройки Git/Cargo.

Если Strawberry Perl не установлен, `python scripts/perl-runtime.py` загружает только компоненты нативного Perl из официального переносимого архива в `.tools/native-perl`. Проверяются целостность ZIP-записей и HTTPS; полный SHA-256 исходного архива при частичной загрузке не проверяется. Инструмент используется только при сборке, не включается в приложение и не меняет системный PATH.

```powershell
npm test
npm run test:e2e
npm run build
```

Сквозной тест настоящего приложения со встроенным интерфейсом:

```powershell
pwsh -File scripts/build-windows.ps1 -Mode build-smoke
node scripts/native-smoke.mjs
```

Для проверки изображений создайте синтетические PNG/JPEG/WebP/GIF командой `python scripts/image-fixtures.py`, задайте `$env:NOT_STUDIO_TEST_ATTACHMENT = (Resolve-Path artifacts/image-fixtures/complete.png).Path` и повторите `node scripts/native-smoke.mjs`. Debug-тест подставляет этот файл вместо системного диалога; шифрование, IPC, декодирование, перетаскивание и сохранение проходят через приложение. Проверяются SHA-256, нижние пиксели изображения, пропорции, обтекание, undo/redo и перезапуск. Test-профиль может работать параллельно открытому личному дневнику. В release эти тестовые возможности отсутствуют.

Он использует синтетические данные в отдельной папке `artifacts/native-test-*`, переживает принудительное завершение и проверяет разблокировку ключом. Эти файлы не используются рабочим дневником. Vite исключает `artifacts`, Rust и инструменты сборки из наблюдения за файлами, чтобы Windows не блокировала перенос временных папок.

Браузерные тесты используют установленный Microsoft Edge и отдельную демонстрацию в памяти. `npm run dev`, затем `http://127.0.0.1:1420/?demo=1` — **только демонстрация**, без постоянного хранения и криптографии. Этот адаптер отсутствует в production-сборке. Обычный браузер не подменяет нативное хранилище.

## Где находятся данные

Windows: `%APPDATA%\studio.not.journal\`.

- `vault/journal.db` — зашифрованная база с записями, индексом и настройками.
- `vault/vault.json` — версия формата, соль и зашифрованные обёртки ключа.
- `vault/files/<UUID>` — зашифрованные вложения; названия и MIME находятся в базе.
- `backups/*.notbackup` — ежедневные копии.
- `previous-*` — предыдущее хранилище после восстановления. Автоматически не удаляется.

Копии на том же диске защищают от ошибочных изменений, но не от потери диска. Для независимой копии выберите другой носитель через настройки. Смена пароля не меняет пароль старых архивов; recovery key продолжает работать для них.

`Ctrl+N` — новая запись; `Ctrl+K` — поиск; `Ctrl+S` — немедленное сохранение; `Ctrl+Alt+↑/↓` — перестановка блока; `Escape` — выход из фокуса. Для форматирования работают стандартные сочетания редактора. Открыв восстановленную копию, введите её пароль или recovery key.

## Границы первой версии

Один локальный дневник; без облака, аккаунтов, телеметрии, совместного редактирования и AI. Файлы добавляются через системный диалог; вставка изображения из буфера предлагает воспользоваться этим действием. Произвольные файлы можно сохранить наружу, встроенный предпросмотр есть у PNG/JPEG/GIF/WebP. Ссылки редактируются в документе и открываются в экспортированном HTML; автоматической загрузки внешних ресурсов нет.

Блокировка работает через 5 минут без действий и по обнаружению блокировки сессии Windows (опрос раз в секунду). Перед блокировкой интерфейс получает до 3 секунд на сохранение. Уже подтверждённые изменения сохраняются; при аварии могут потеряться ещё не подтверждённые правки. При ручном закрытии или блокировке ошибка сохранения оставляет приложение открытым для повторной попытки.

Для macOS/Linux предусмотрено разделение UI и системного слоя, но сборка и интеграция блокировки сессии на этих ОС ещё не проверены. Проверка именно на Windows 11, полная матрица масштабов рабочего стола 100%/150%/200% и двухнедельное ежедневное использование требуют отдельной приёмки. Браузерные проверки узких окон не заменяют эти проверки.
